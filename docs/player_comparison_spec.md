# 선수 스탯 비교 기능 — 웹디자인 명세

> 이 문서는 사용자가 직접 구술한 구현 목표만을 기반으로 작성되었습니다.
> 기존 디자인 가이드(`WEBDESIGN_GUIDE.md`, `kleague-design-agent.md`)와 무관하게 별도로 관리합니다.

---

## 1. 구현 목표 (핵심 기능)

**K리그 선수의 각종 스탯을 유저가 직접 선택해서 비교하는 기능**이 이 페이지의 핵심이다.
유저는 비교할 선수와 비교할 스탯을 모두 자유롭게 선택할 수 있어야 한다.

---

## 2. 선수 선택 플로우

선수는 다음 4단계 드릴다운 방식으로 선택한다.

```
시즌 선택  →  리그 선택  →  팀 선택  →  선수 선택
```

- 각 단계는 이전 단계 선택 결과에 따라 옵션이 좁혀진다.
- **최대 3명까지** 선수를 선택할 수 있다.
- 선수를 추가/제거할 수 있는 슬롯 UI 형태(예: "Add Player" 카드)로 구성한다.

---

## 3. 스탯 선택 플로우

스탯은 2단계 카테고리 방식으로 선택한다.

```
1레벨 카테고리  →  2레벨 카테고리(세부 스탯)
```

### 1레벨 카테고리 (대분류)
- 슈팅
- 패스
- 수비

### 2레벨 카테고리 (세부 스탯) — POC 잠정 정의
- **슈팅**: 슈팅 / 유효슈팅 / 득점 / PA내 슈팅 / PA외 슈팅
- **패스**: 패스 시도 / 패스 성공 / 키패스 / 롱패스 시도 / 크로스
- **수비**: 태클 / 인터셉트 / 클리어링 / 차단 / 공중경합 승리

> 시안 구현에서는 위 목록을 사용(`demo html/comparison-data.js` `CAT_STATS`). 실제 DB 컬럼과 매핑은 추후 확정.
> UI: 1레벨은 버튼, 2레벨은 **드롭다운 체크리스트**(다중 선택, 기본 전체 선택)로 매트릭스 행을 구성.

---

## 4. 스탯 비교 단위

유저는 아래 3가지 단위 중에서 비교 기준을 전환할 수 있어야 한다.

| 단위 | 설명 |
|------|------|
| 90분당 횟수 | 출전 시간 대비 환산값 (Per 90) |
| 전체 합계 | 시즌 누적 총합 (Total) |
| 백분위 | **선택 시즌 전체 선수 기준** 백분위(percentile) |

---

## 5. 시각화 방식

두 가지 안을 모두 후보로 둔다.

### 1안 — 그리드 히트맵
- 선택한 선수들의 스탯을 그리드 스타일 히트맵으로 비교.
- 값의 크기를 색 농도로 표현.

### 2안 — 바차트
- 선택한 선수들의 스탯을 바차트 형식으로 비교.

### 시각화 레퍼런스 — Squawka Matrix Comparison (구조/레이아웃만 차용)

> ⚠️ Squawka 의 **색상(보라/흰 배경)은 쓰지 않는다.** 레이아웃·컴포넌트 구조만 차용하고,
> 색·분위기·폰트는 6번(K리그 데이터포털)을 따른다.

첨부 스크린샷에서 추출한 구조 토큰:

**전체 레이아웃**
- 상단 좌측: 페이지 타이틀(`COMPARISON MATRIX` 위치). 상단 우측: `공유` 버튼(아이콘 + 라벨).
- 타이틀 하단: **세그먼트 토글** — 활성 탭은 채움(filled), 비활성은 흐린 배경. 우리 안에서는 `전체 합계 / 90분당 / 백분위` 3분할.
- 선수 카드를 **가로로 나란히 배치**(최대 3장) + 마지막에 **빈 "선수 추가" 슬롯**.

**선수 카드 — 헤더 영역**
- 카드 상단 배너: 팀 엠블럼, 선수명(굵게), 포지션, 데이터 출처 라벨, 우상단 `제거 ✕` 버튼.
- 원본은 배너에 보라 그라데이션 + 다이아몬드 메시 패턴 → **우리 안에서는 다크 배너 + (팀 컬러 accent) + 데이터포털식 사선 모티브로 대체.**

**선수 카드 — 바디 영역**
- 상단에 **드롭다운 2개**: 팀(`Arsenal ▼`), 시즌(`2025/2026 ... ▼`). 우리 안에서는 4단계 선택(시즌→리그→팀→선수) 결과를 여기에 표기/수정.
- 그 아래 **스탯 행 반복**. 각 행 = `스탯명(좌) + 값(우)` + 바로 아래 **가로 진행 바**.
- **최고값 강조**: 선택된 선수들 중 최댓값에 `★` 접두 + 강조색 바. 나머지는 흐린/무채색 바.
  - 원본은 best=초록 / 그 외=빨강. **우리 안에서는 best=강조 accent / 그 외=뮤트 그레이**로 단순화(빨강은 '나쁨' 오해 소지 → 지양).

**선수 추가 슬롯**
- 점선(dashed) 둥근 테두리 카드 + 가운데 `사람+` 아이콘 + `선수/팀 추가` 라벨.

> 이 Squawka 구조는 **2안(바차트)** 과 사실상 동일하다. 즉 2안 = "세로 카드 + 스탯별 가로 바" 형태로 구현하면 레퍼런스와 일치한다.
> **1안(그리드 히트맵)** 은 카드 대신 `행=스탯 / 열=선수` 표 형태에 셀 색 농도로 값을 표현하는 별도 레이아웃.

## 6. 디자인 스타일 — K리그 데이터포털 (색·분위기·폰트의 단일 기준)

`kleague.com/about/reference.do` 페이지에서 **개발자도구 computed style로 직접 추출한 실제 값**.
(2026-06-03 확인. 스크린샷 추정이 아니라 사이트에서 뽑은 확정값.)

> 💡 포털 실측 결과 **브랜드 컬러는 레드가 아니라 네이비(`#001C48`)** 였다(이전 '레드 추정'은 폐기).
> 또한 포털 본문은 사실 라이트 영역이고, **다크는 네비바·히어로·푸터**에 쓰인다. 사용자가 원하는 건
> 이 "다크 영역의 무드"이므로, 우리 앱은 그 다크 톤을 전면에 깔고 네이비를 accent로 쓴다.

### 무드
- 거의 검정에 가까운 **다크 배경 기반**, 무게감 있고 절제된 톤.
- 헤더(히어로) 영역에 **사선/각진 그래픽 모티브** — 배경보다 약간 밝은 회색 슬래시가 대각선으로 흐른다.
- 채도 낮은 무채색 위주 + 포인트는 네이비. 강조는 최소한으로.

### 색상 토큰 (실측값)
| 토큰 | 값 (rgb → hex) | 용도 |
|------|----------------|------|
| `bg-base` | `rgb(10,10,10)` `#0A0A0A` | 페이지 최하단 배경 (가장 깊은 다크) |
| `bg-elevated` | `rgb(18,18,18)` `#121212` | 상단 네비바·푸터 |
| `surface-card` | `rgb(28,28,28)` `#1C1C1C` | 카드·패널 표면 (포털 최빈 다크) |
| `surface-hover` | `rgb(48,48,48)` `#303030` | 카드/행 호버·칩 배경 |
| `border-dark` | `rgb(118,118,118)` `#767676` | 다크 위 구분선 |
| `accent` | `rgb(0,28,72)` `#001C48` | **브랜드 네이비** — 활성 탭·강조·best 값 |
| `accent-hairline` | `rgba(0,28,73,0.1)` | 네이비 10% 헤어라인 구분선 |
| `text-primary` | `rgb(255,255,255)` `#FFFFFF` | 다크 위 주요 텍스트 |
| `text-secondary` | `rgba(255,255,255,0.6)` | 다크 위 부제·라벨 |
| `text-muted` | `rgb(115,115,115)` `#737373` | 비활성·캡션 |
| `text-caption` | `rgb(142,142,142)` `#8E8E8E` | 보조 캡션 |
| *(라이트 영역 사용 시)* `text-on-light` | `rgb(34,34,34)` `#222222` | 흰 배경 위 본문 |
| *(라이트 영역 사용 시)* `border-light` | `rgb(227,229,233)` `#E3E5E9` | 흰 배경 위 구분선 |

### 타이포그래피 (실측 — `font-family` 그대로)
- **국문 본문/메뉴**: `Noto Sans KR` (weight 300 / 400 / 500 / 700 / 900 로드됨), fallback `Arial`.
- **영문 헤딩/워드마크**: 원본은 `Campton`(유료) → **라이선스 미보유로 무료 `Montserrat` 로 대체 확정.**
  성격이 가장 가까운 지오메트릭 산세리프. `ABOUT K LEAGUE` 같은 굵은 대문자 타이틀에 사용.
- **숫자/라틴 보조**: `Roboto` (400/500/700) — 스탯 수치 표기에 활용 가능.
- 실제 스택: 본문 `font-family: "Noto Sans KR", Arial, sans-serif;` / 영문 헤딩 `"Montserrat", "Noto Sans KR", sans-serif;`
- 위계: 큰 볼드 제목(Montserrat/대문자) ↔ 한 단계 작고 흐린(`text-secondary`) 부제 조합(예: 한글 제목 + 우측 영문 라벨 `Reference`).

### 레이아웃 패턴 (포털에서 차용)
- 상단 풀폭 다크 네비바: 좌측 로고 → 중앙 메뉴 → 우측 검색/언어 칩.
- 섹션 헤더: 좌측 굵은 국문 라벨 + 우측 흐린 영문 라벨(`자료실 / Reference` 패턴).
- 콘텐츠는 넓은 좌우 여백 안에서 풀폭에 가깝게 배치.

## 7. 미확정 / 추후 정의 항목
