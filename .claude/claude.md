# 프로젝트 규칙

## 문서 파일 안내

| 파일 | 역할 | 참조 시점 |
|------|------|-----------|
| `docs/CHANGELOG.md` | 버전별 변경 이력 릴리즈 노트 | 기능 추가·수정·버그 수정 내역 확인 시 |
| `docs/schema.md` | DB 테이블 정의, ERD, 적재 현황 명세 | 쿼리 작성·테이블 설계·ETL 수정 전 |
| `docs/scripts.md` | ETL·수집 스크립트 역할·함수·의존 관계 레퍼런스 | 어떤 스크립트를 실행할지 판단하거나 스크립트 수정 전 |
| `docs/todo_list.md` | 데이터 정합성 이슈·품질 개선 이슈 트래커 | 신규 작업 착수 전 기존 알려진 이슈 확인 시 |
| `docs/WEBDESIGN_GUIDE.md` | 모드 제약·타이포·레이아웃·컴포넌트 규칙 SSoT | 웹 페이지·컴포넌트 구현 전 반드시 확인 |
| `docs/kleague-design-agent.md` | 웹디자인 POC 서브에이전트 지시문 (역할·컴포넌트·산출물 규칙) | 웹 대시보드 샘플 생성·개선 요청 시 반드시 먼저 읽을 것 |

## 문서 업데이트 규칙

작업 완료 후 변경사항이 있을 경우 반드시 해당 파일을 업데이트한다.
포맷은 각 파일의 기존 형식을 직접 확인하여 맞춘다.

- `docs/CHANGELOG.md` — 기능 추가·수정·버그 수정·데이터 적재 완료 등 모든 변경 시
- `docs/schema.md` — 테이블·컬럼 추가·삭제·수정, FK·UNIQUE 제약 변경, 적재 현황 수치 변경 시
- `docs/scripts.md` — 스크립트 추가·수정·삭제, 함수·파라미터 변경, `_archive/` 이동 시
- `docs/todo_list.md` — 새 이슈 발견 시 추가, 이슈 해결 완료 시 해당 항목 삭제
- `docs/WEBDESIGN_GUIDE.md` — 모드 규칙·컴포넌트 스펙 변경, 페이지 구현 완료, API 엔드포인트 확정 시
- `docs/kleague-design-agent.md` — 에이전트 역할·트리거·산출물 규칙 변경 시

---

## ⚠️ 필수 작업 완료 체크리스트

모든 작업 마무리 전 반드시 확인:
- [ ] `docs/CHANGELOG.md`에 변경사항 기록했는가?
- [ ] DB 스키마 변경이 있었다면 `docs/schema.md` 반영했는가?
- [ ] 스크립트 추가·수정이 있었다면 `docs/scripts.md` 반영했는가?
- [ ] 이슈를 해결했거나 새 이슈를 발견했다면 `docs/todo_list.md` 갱신했는가?
- [ ] 웹 디자인·컴포넌트 변경이 있었다면 `docs/WEBDESIGN_GUIDE.md` 반영했는가?

위 항목을 완료하지 않으면 작업이 끝난 것이 아니다.

## 웹디자인 POC 에이전트 규칙

웹 대시보드·UI 샘플 생성 요청 시 아래 절차를 따른다.

### 참조 파일 (우선순위 순)
1. `docs/kleague-design-agent.md` — 역할 정의, 컴포넌트 목록, 산출물 형식
2. `docs/WEBDESIGN_GUIDE.md` — 모드 제약, 타이포, 레이아웃 기준

### 트리거 키워드
아래 요청이 들어오면 `kleague-design-agent.md`를 먼저 읽고 작업한다.
- "대시보드 샘플 만들어줘" / "새로운 디자인 버전 생성해줘"
- "레퍼런스 탐색 후 UI 개선해줘" / "선수 비교 카드 컴포넌트 만들어줘"
- "Streamlit 버전으로 변환해줘" / "React 컴포넌트로 변환해줘"

### 색상 원칙
- **다크 / 라이트 두 모드만 허용** — 혼용 금지
- 모드 내 구체적 색상(accent, card, border, P1/P2/P3)은 레퍼런스 기반 자유 결정
- K리그 아이덴티티 색상: 미확정, 추후 반영

### 산출물 규칙
1. HTML 파일은 `demo html/` 하위 저장
2. 파일 상단 버전 헤더 필수: `<!-- v1.0 | 날짜 | 레퍼런스: ... | 변경: ... -->`
3. 컴포넌트 경계 주석 필수: `<!-- COMPONENT: Name --> ... <!-- /COMPONENT: Name -->`
4. 단계 순서: HTML 정적 → React 컴포넌트 → Streamlit
5. 매 생성마다 개선 후보 3가지 제안

- [ ] 버전 헤더를 파일 상단에 포함했는가?
- [ ] 컴포넌트 경계 주석을 달았는가?
- [ ] 개선 후보 3가지를 제안했는가?
